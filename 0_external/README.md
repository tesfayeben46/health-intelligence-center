# External systems

Everything in this directory runs outside the k8s cluster, as Docker Compose stacks on the host. These are the systems the platform integrates with but would not operate in production: the source systems the ingestors pull from, the national-ID provider used for identity verification, and the model server behind the dashboard assistant. In-cluster pods reach them through `host.k3d.internal`; none of the stacks joins the platform's own Docker network.

The software is real where noted below. **All data in these systems is demonstration data**: generated by scripts in this directory or restored from artifacts that are distributed separately. See [`docs/data-provenance.md`](../docs/data-provenance.md) for how each source reaches the warehouse.

## Layout

```
sources/DHIS2/      DHIS2 2.40 + PostGIS (aggregate HMIS; also hosts IDSR and population data)
sources/IDSR/       seeders that write weekly IDSR surveillance and woreda populations into DHIS2
sources/Climate/    small FastAPI service serving a generated weekly climate series
sources/HCMISWDM/   SQL Server 2025 hosting HCMISWDM (EPSS warehouse) and, beside it, mBrana's database
sources/mBrana/     restore and synthesis scripts for mBrana's HCMISWCloud database (no compose file)
sources/EthioEMR/   MySQL 8 with the OpenMRS schema (no OpenMRS application)
sources/MFR/        HAPI FHIR R4 facility registry
sources/OpenLMIS/   PostgreSQL 16 with a Zambian eLMIS historical star schema
fayda/              OIDC and e-mail OTP service modelling the Fayda national-ID flow
llm/                Ollama serving Qwen 2.5 for the dashboard assistant
```

## Replicas and how they are seeded

| Replica | What runs | How it is seeded | Fresh clone |
|---|---|---|---|
| DHIS2 | `dhis2/core` 2.40 with `postgis/postgis:14-3.3` | `DHIS2/scripts/seed_ethiopia.py` writes the org-unit tree, data elements, the HMIS Monthly data set and generated monthly values through the REST API, then runs `IDSR/seed_idsr_dhis2.py` (weekly cases with injected outbreaks and rainfall coupling) and `IDSR/seed_population_dhis2.py` (deterministic woreda populations). A packed `sample-data/dhis2_seeded.pgdump`, if present, is restored instead. | Seeds itself |
| Climate | `climate-api` (FastAPI, built from `Climate/api/`) | `Climate/generate_climate.py` writes a deterministic weekly series to `bundle/seeds/sources/climate/weekly.csv`, which the API serves | Seeds itself |
| HCMIS WDM | SQL Server 2025 Developer (`hcmiswdm-sqlserver`); schema only, no HCMIS application | `HCMISWDM/scripts/restore.sh` restores the schema from `sample-data/HCMISWDM.bak`; `synthesize.py`, `synthesize_analytics.py` and `synthesize_dispatch.py` generate every row | Needs the schema backup, distributed separately |
| mBrana | Database `HCMISWCloud` in the same SQL Server container | `mBrana/scripts/restore.sh` restores the schema from `sample-data/HCMISWCloud.bak`; `synthesize.py` generates the rows | Needs the schema backup, distributed separately |
| EthioEMR | MySQL 8.0 (`ethioemr-mysql`) with the OpenMRS schema; no OpenMRS application | `EthioEMR/scripts/restore.sh` loads `sample-data/clean_openmrs.sql` (schema, concept dictionary, module configuration); `synthesize.py` generates patients, visits, encounters and observations | Needs the dump, distributed separately |
| MFR | HAPI FHIR R4 (`hapiproject/hapi:v8.0.0`) on H2 | `MFR/scripts/seed.py` posts Organization resources for the shared entity model's regions, zones, woredas and facilities, with derived staffing figures | Seeds itself |
| eLMIS | PostgreSQL 16 (`elmis-postgres`) | `OpenLMIS/scripts/restore.sh` streams the historical extract `sample-data/elmis_historical_data_simulated.sql.gz` if present; otherwise `OpenLMIS/scripts/synthesize.sh` generates an equivalent Zambian history from committed files | Seeds itself through the fallback generator |
| Fayda | `fayda-replica` (FastAPI, built from `fayda/`) | Synthetic citizens from `fayda/seed/citizens.yaml`, loaded at start-up | Seeds itself |
| Assistant model | `ollama/ollama:0.6.8` (`nhdw-ollama`) | Public Qwen 2.5 weights in `llm/models/` (bundled, or pulled at bring-up) | Seeds itself (online) |

Generators draw facilities, programmes, commodities and periods from the shared demonstration entity model in `bundle/seeds/entity-model/`, which is why records line up across sources. The Ethiopian generators are deterministic for a given entity-model seed. Restore artifacts are excluded from the repository (see `.gitignore` and each `sample-data/SEED-DATA-NOTICE.md`); they hold schemas and, for a packed bundle, previously generated rows.

## Bring-up

`bootstrap.sh` calls `bundle/scripts/sources-up.sh up` after the cluster exists. It brings up the LLM, Fayda, Climate, MFR, EthioEMR, HCMIS WDM with mBrana, eLMIS and DHIS2 (slowest, last), creating each source's `.env` from `.env.example` when missing. For each SQL source it restores the artifact and then synthesizes only when the database lacks rows stamped with the current synthesizer version and country profile.

```bash
bundle/scripts/sources-up.sh up            # every stack
bundle/scripts/sources-up.sh up dhis2      # one of: llm dhis2 ethioemr hcmis mfr climate elmis
bundle/scripts/sources-up.sh down          # stop every stack; add --wipe to delete volumes
```

Each source directory also has its own `scripts/` for manual restore, synthesis and verification; see its README.

## Ports

| Port | Service |
|---|---|
| 8080, 5433 | DHIS2 web, DHIS2 database |
| 8095 | Climate API |
| 1433 | SQL Server (HCMISWDM and HCMISWCloud) |
| 33306 | EthioEMR MySQL |
| 8093 | MFR FHIR |
| 5434 | eLMIS PostgreSQL |
| 8096 | Fayda |
| 11434 | Ollama |

Most ports are published on `0.0.0.0` so k3d pods can reach them through `host.k3d.internal`. Bind them to a private interface on any shared host.

## Notes

- Credentials in `.env.example`, `.env.template`, `dhis.conf` and compose defaults are placeholders for local use. The reader passwords must match the `source-creds` Secret the in-cluster ingestors use.
- For a non-default country profile, `sources-up.sh` skips the Ethiopia-only HCMIS WDM and mBrana sources, and Climate when its CSV has not been generated.
- eLMIS carries Zambian data; it does not join the Ethiopian entity model. See `sources/OpenLMIS/README.md`.

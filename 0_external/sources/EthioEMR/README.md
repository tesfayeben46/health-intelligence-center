# EthioEMR source replica

Stands in for EthioEMR, the facility electronic medical record system (an OpenMRS distribution). The replica is **MySQL 8.0 with the OpenMRS schema only**: no OpenMRS web application runs, so there are no REST or FHIR endpoints. The EthioEMR ingestor (`2_pipelines/ingestor/EthioEMR`) reads the clinical tables directly over the MySQL wire, as a real deployment exposes them for CDC or direct extract, and reshapes the rows into FHIR-shaped Parquet.

**All clinical data is synthetic.** The dump supplies the schema, concept dictionary and module configuration; patients, providers, visits, encounters, observations, orders and programme enrolments are generated by `scripts/synthesize.py`.

## Layout

```
docker-compose.yml        mysql:8.0 (container ethioemr-mysql), port 33306, binlog + GTID on
.env.example              root, reader and app passwords; synthesis controls
init/01-create-users.sql  user provisioning written for docker-entrypoint-initdb.d (not mounted)
sample-data/              restore artifact clean_openmrs.sql (distributed separately)
schema/README.md          schema notes and table groups
scripts/restore.sh        loads the dump and provisions the ingestor and openmrs users
scripts/synthesize.py     generates the clinical rows on top of the restored schema
scripts/verify.sh         reader connectivity and row counts
scripts/reset.sh          drops the volume and restores again
```

## Seeding

The dump is not in the repository (see `sample-data/SEED-DATA-NOTICE.md`), so a fresh clone cannot seed this source until it is supplied.

```bash
cd 0_external/sources/EthioEMR
cp .env.example .env
docker compose up -d
bash scripts/restore.sh          # drop and recreate `openmrs`, import the dump, create users
python3 scripts/synthesize.py    # generate the clinical rows
bash scripts/verify.sh
```

`bundle/scripts/sources-up.sh up ethioemr` does the same. It runs `synthesize.py` unless the restored database already carries observations stamped (in `openmrs.synth_meta`) with the current `SYNTH_VERSION` and country profile. A non-empty database without the marker is kept, with a warning.

## What the generator writes

`synthesize.py` draws facilities, programmes, commodities and the period window from the shared entity model (`bundle/seeds/entity-model/_build/`):

- `location` rows for health centres and hospitals, with the shared `facility_id` and `mfr_id` encoded in `address1`;
- providers and patients with generated Ethiopian names, addresses at the patient's facility and identifiers;
- 1 to 8 visits per patient, 1 to 3 encounters per visit, 3 to 12 numeric observations per encounter against concepts present in the dump;
- drug orders on about 70% of ART refill, consultation and ANC encounters, using `drug` rows whose `name` is the shared `commodity_id`;
- HIV, TB, MNCH and NCD enrolments by cohort rule, NCD problem-list conditions and allergy flags.

It deletes previously generated rows first and loads everything in one transaction, then stamps `synth_meta`.

## Configuration

| Variable | Default in `.env.example` | Purpose |
|---|---|---|
| `ETHIOEMR_MYSQL_ROOT_PASSWORD` | placeholder | MySQL root |
| `ETHIOEMR_READER_USER` / `_PASSWORD` | `ingestor` | read-only user with SELECT and replication grants; must match the `source-creds` Secret |
| `OPENMRS_DB_PASSWORD` | placeholder | `openmrs` user created by `restore.sh` |
| `ETHIOEMR_SYNTH_PATIENT_COUNT` | 500 | patients (script default 1500) |
| `ETHIOEMR_SYNTH_LOCATION_COUNT` | 30 | facilities to use (0 means all eligible) |
| `ETHIOEMR_SYNTH_PROVIDER_COUNT` | 20 | providers |
| `ETHIOEMR_SYNTH_SEED` | 42 | random seed (script default: entity-model seed) |

## Notes

- MySQL runs with `innodb-strict-mode=0` and dynamic row format because some module tables in the dump exceed InnoDB's row-size limit.
- The port is published on `0.0.0.0:33306` so k3d pods reach it through `host.k3d.internal`.
- The concept IDs, encounter types and programme IDs referenced by `synthesize.py` are those present in the dump.

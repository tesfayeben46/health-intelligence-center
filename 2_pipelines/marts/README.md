# Marts (dbt)

The dbt project `nhdw_marts` builds the `bi_*` serving schemas in Postgres (`postgres-vault`, database `nhdw_vault`) from the Data Vault. Marts read hubs and links from `nhdw_vault_raw`, satellite attributes only through the business-vault `v_*_current` views, and the conformed spine, dimensions and resolution views from `nhdw_vault_business` (sources in `models/_sources_vault.yml`). Trino and the gateway read the result as `bi_reader`.

All data the marts carry is derived from the demonstration data described in [docs/data-provenance.md](../../docs/data-provenance.md). Figures in the eLMIS and PCT supply-chain marts (PCT: the supply-planning layer behind the Supply Control Tower, `mart_pct_*`) describe the Zambian eLMIS archive, which is kept separate from the Ethiopian entity model.

## Layout

| Path | Purpose |
|---|---|
| `dbt_project.yml` | Schemas, materialisation, owner and grant post-hooks, `persist_docs` |
| `models/<domain>/` | Internal marts, one directory per subject area |
| `models/<domain>/public/` | k-anonymised projections of the domain, schema `bi_public` |
| `models/_sources_vault.yml` | Vault, governance, ML and plan-decision sources |
| `models/_exposures.yml` | Widget-to-mart exposures, generated by `bundle/scripts/gen-exposures.py`; do not edit by hand |
| `seeds/` | Reference and contract CSVs (see Seeds) |
| `macros/` | `consent_gate` (anti-join against consent revocations) and `generate_schema_name` (schema names used verbatim) |
| `tests/` | Singular data tests |
| `entrypoint.py` | Image entry point: runs dbt, uploads `target/` artifacts, generates dbt docs |
| `publish_public_datasets.py` | Exports the public marts as CSV with a catalogue |
| `profiles/profiles.yml` | dbt-postgres profile, configured from `PG_*` environment variables |

## Schemas and materialisation

Models default to views. Domains that aggregate heavily are tables. Every model gets two post-hooks: `ALTER ... OWNER TO vault_admin`, so a view never belongs to a short-lived database user, and `GRANT SELECT ... TO bi_reader`. `persist_docs` writes each `description:` into Postgres comments, which the Internal BI dataset catalogue reads. The `bi_*` schemas are declared in `3_storage/postgres/init/` (`01_schemas.sql`, `07_marts_schemas_extras.sql`).

| Directory | Schema | Materialisation |
|---|---|---|
| `data_quality/` | `bi_quality` | table |
| `facility_distribution/` | `bi_facility` | view (public projections are tables) |
| `governance/` | `bi_governance` | table |
| `hmis_coverage/` | `bi_hmis` | table |
| `idsr/` | `bi_idsr` | table |
| `mdm/` | `bi_mdm` | view, with tables for the candidates and the golden record |
| `service_performance/` | `bi_service` | table |
| `staging/` | `bi_staging` | view; models here await promotion through the gateway graduation flow |
| `supply_chain/` | `bi_supply` | view, with tables for the eLMIS, PCT and Control Tower marts |
| `*/public/` | `bi_public` | table, so Trino's Postgres connector reads aggregate column types reliably |

## Tests

Column tests live in each `_models.yml`. Singular tests in `tests/`:

| Test | Asserts |
|---|---|
| `cascade_monotonicity.sql` | Cascade steps do not exceed the previous step (5% headroom) |
| `elmis_timeliness_is_measured.sql` | eLMIS keeps a measured timeliness row in `mart_data_quality` and stays out of the public projection |
| `integration_load_loss.sql` | The vault data-value link holds at least 95% of distinct landing fact rows |
| `k_anonymity_public_marts.sql` | Every group represents at least 5 facilities, in four of the eight `bi_public` marts (`bi_facility_distribution_public`, `mart_public_indicator_kpis`, `mart_public_summary`, `mart_supply_stockout_public`) |
| `ml_disease_input_densification.sql` | `mart_ml_disease_input` is the full woreda, disease and week grid |

## Running

The image `nhdw/marts-dbt` (built by `bundle/scripts/build-images.sh`) runs as the Kubernetes Job `dbt-marts` in `1_infrastructure/k8s/base/dbt-jobs.yaml`, after `dbt-vault`. The Job runs `ANALYZE`, then `entrypoint.py build`, adding `--full-refresh` only on a cold database. `entrypoint.py` forwards its arguments to dbt, uploads `manifest.json`, `run_results.json` and `catalog.json` to `nhdw-artifacts/dbt/marts/` for the gateway's `/api/dq/*` endpoints and the OpenMetadata dbt connector, and writes the dbt docs site to the shared `dbt-docs-content` volume when `DBT_DOCS_OUT` is set. Both steps are best effort and do not change dbt's exit status.

`publish_public_datasets.py` runs afterwards as the `publish-datasets` Job. It exports each public mart listed in its `DATASETS` catalogue as CSV to the `nhdw-static` bucket, with `catalogue.json` carrying source, grain, period, row count, licence and download URL. Identifiers use DataCite's test prefix `10.5072`.

Configuration comes from the environment: `PG_HOST`, `PG_PORT`, `PG_USER`, `PG_PASSWORD`, `PG_DATABASE` for dbt and the publisher (`.env.example` shows the shape), and `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY` and `DBT_PROJECT` for the artifact upload. The `MINIO_*` names are historical; the object store is SeaweedFS.

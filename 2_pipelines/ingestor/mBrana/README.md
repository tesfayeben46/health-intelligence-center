# mBrana ingestor

Extracts mBrana's `HCMISWCloud` SQL Server database (community-level USSD stock reporting plus its institution, product and administrative masters) and writes each table as Parquet to the `nhdw-raw` bucket of the data lake (SeaweedFS, S3 API). mBrana has no REST or FHIR API, so the ingestor reads over TDS with dlt's `sql_database` source, pyodbc and Microsoft ODBC Driver 18. Its structure matches the HCMIS WDM ingestor.

The database it reads is the `HCMISWCloud` schema restored into the HCMIS WDM SQL Server container (see `0_external/sources/mBrana/`): the schema comes from a schema-only backup (distributed separately) and every row is generated by `0_external/sources/mBrana/scripts/synthesize.py` from the shared demonstration entity model. See [docs/data-provenance.md](../../../docs/data-provenance.md).

## Layout

| Path | Purpose |
|---|---|
| `src/cli.py` | Entry point: `python -m src.cli extract [--only a,b]` |
| `src/config.py` | Environment variables and the SQLAlchemy URL |
| `src/pyodbc_setup.py` | Registers pyodbc converters for `hierarchyid`, `geometry` and `geography` (returned as hex strings) |
| `src/destination.py` | dlt filesystem destination and the lake path layout |
| `src/manifest.py` | `_manifest.json` sidecar writer |
| `src/lineage.py` | Optional OpenMetadata lineage emitter |
| `src/pipelines/tables.py` | Explicit table allowlist |
| `src/pipelines/extract.py` | The `extract` pipeline |

## Tables

The allowlist in `src/pipelines/tables.py` is the complete list; each lake table is named `<schema>_<table>` in lower case (for example `mflowussd_sohlogs`). An explicit list keeps framework tables (HangFire, Temp, `dbo.AspNet*`) out of the lake, stops new source tables from entering the warehouse unreviewed, and makes the file's history the schema-change record.

| Schema | Tables |
|---|---|
| `AdministrativeUnit` | `AdministrativeUnit` |
| `dbo` | `Region`, `Zone`, `Woreda`, `Institution` |
| `Commodity` | `CommodityType`, `Product` |
| `Institution` | `OwnershipType` |
| `USM` | `Environment`, `EnvironmentGroup` |
| `mBrana` | `InstitutionEnvironment`, `SiteStatus`, `TrendStatus` |
| `mFlowUSSD` | `Users`, `Institutions`, `Commodities`, `Requests`, `RequestLines`, `ASNs`, `ASNLines`, `SOHLogs` |

`mFlowUSSD.SOHLogs` is the stock-on-hand fact the vault loads as `lnk_mbrana_stock_event`. Every table is replaced on each run, for the reasons given in the HCMIS WDM ingestor README; the `cursor` field in `TableSpec` is not read by `extract.py`.

## Output

```
s3://nhdw-raw/mbrana/<schema_table>/year=YYYY/month=MM/day=DD/mbrana_<schema_table>_<ts>_run-<id>_part-<hash>.parquet
s3://nhdw-raw/mbrana/<schema_table>/year=YYYY/month=MM/day=DD/_manifest.json
```

The processed-zone Job drops contact numbers, tax identifiers, user names and data-entry usernames from the institution, admin and USSD user tables (`2_pipelines/staging/scripts/pii_policy.yaml`).

## Running

The Kubernetes Job `mbrana-ingest` in `1_infrastructure/k8s/base/ingestor-jobs.yaml` runs the image with args `["extract"]`. It connects to `host.k3d.internal:1433`, database `HCMISWCloud`, as the read-only `ingestor` login that `0_external/sources/mBrana/scripts/restore.sh` provisions; the password comes from the `source-creds` Secret.

The image is `nhdw/mbrana-ingestor`, built by `bundle/scripts/build-images.sh`; it bundles ODBC Driver 18. Outside the cluster:

```bash
docker run --rm --env-file .env nhdw/mbrana-ingestor:1.0.0 extract
docker run --rm --env-file .env nhdw/mbrana-ingestor:1.0.0 extract --only dbo_institution,mflowussd_sohlogs
```

## Configuration

`.env.example` lists every variable.

| Variable | Default | Meaning |
|---|---|---|
| `MBRANA_HOST` | required | SQL Server host |
| `MBRANA_PORT` | `1433` | SQL Server port |
| `MBRANA_DATABASE` | required | Database (`HCMISWCloud`) |
| `MBRANA_USER`, `MBRANA_PASSWORD` | required | Read-only login |
| `MBRANA_DRIVER` | `ODBC Driver 18 for SQL Server` | ODBC driver name |
| `MBRANA_TRUST_SERVER_CERTIFICATE` | `yes` | Accept the replica's self-signed certificate; set `no` with a CA-signed one |
| `MBRANA_TIMEOUT` | `120` | Connection timeout in seconds |
| `MINIO_ENDPOINT` | required | S3 endpoint of the lake |
| `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY` | required | Object-store credentials |
| `MINIO_RAW_BUCKET` | `nhdw-raw` | Target bucket |
| `MINIO_REGION` | `et-addis-1` | S3 region name |
| `DLT_PIPELINE_NAME` | `mbrana` | Prefix of dlt's pipeline state |
| `OM_LINEAGE_API`, `OM_LINEAGE_JWT` | unset | Enable lineage emission to OpenMetadata |

The `MINIO_*` names are historical; the object store is SeaweedFS.

## SQL Server specifics

| Issue | Handling |
|---|---|
| pyodbc cannot decode `hierarchyid` (type -151), `geometry` (-150), `geography` (-152) | `src/pyodbc_setup.py` registers converters that return hex strings; it is imported from `src/__init__.py` before any dlt or SQLAlchemy code runs |
| ODBC Driver 18 encrypts by default and rejects a self-signed certificate | `MBRANA_TRUST_SERVER_CERTIFICATE=yes` against the replica |

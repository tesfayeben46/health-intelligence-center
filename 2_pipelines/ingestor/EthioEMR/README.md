# EthioEMR ingestor

Reads the facility EMR (OpenMRS schema on MySQL) directly over MySQL and reshapes each row into the FHIR R4 resource shape that the staging and vault models parse. dlt flattens the resources and writes them as Parquet to the `nhdw-raw` bucket of the data lake (SeaweedFS, S3 API).

An EMR's native integration surface is CDC/JDBC on its database, so the ingestor reads the clinical tables instead of running the OpenMRS web application to serve FHIR. The replica in `0_external/sources/EthioEMR/` is MySQL 8 with the OpenMRS schema and concept dictionary restored from a dump; patients, visits and observations are generated by `0_external/sources/EthioEMR/scripts/synthesize.py`. No real patient data is involved; see [docs/data-provenance.md](../../../docs/data-provenance.md).

## Layout

| Path | Purpose |
|---|---|
| `src/cli.py` | Entry point: `python -m src.cli extract` |
| `src/config.py` | Environment variables, read once into a `Config` |
| `src/destination.py` | dlt filesystem destination and the lake path layout |
| `src/manifest.py` | `_manifest.json` sidecar writer |
| `src/lineage.py` | Optional OpenMetadata lineage emitter |
| `src/pipelines/_mysql.py` | `OpenMRSReader`: streams OpenMRS tables and yields FHIR-shaped dicts |
| `src/pipelines/extract.py` | The `extract` pipeline: one dlt resource per configured FHIR type |

## Tables

`ETHIOEMR_MYSQL_RESOURCES` (default `Patient,Encounter,Observation`) selects the resources:

| Table | FHIR resource | OpenMRS source tables |
|---|---|---|
| `patient` | Patient | `patient`, `person`, `person_name` |
| `encounter` | Encounter | `encounter`, `person`, `visit`, `location`, `patient_identifier` |
| `observation` | Observation | `obs`, `person`, `encounter`, `concept_name`, `concept_numeric` |

Each reader yields a nested dict that mirrors the FHIR JSON. dlt's snake_case naming flattens it with `__` as the nesting separator, giving the columns the staging models expect, for example `meta.lastUpdated` to `meta__last_updated` and `valueQuantity.value` to `value_quantity__value`.

Two rules keep the Parquet schema stable:

1. Every FHIR leaf is emitted on every row, as `""` when absent. dlt drops columns that are NULL in every row, and the raw ClickHouse views are `SELECT * FROM s3(...)`, so a dropped column would break the staging model that references it.
2. Every leaf is a string. Typing happens downstream.

Identity and references follow FHIR conventions, so the vault links (`lnk_encounter_patient`, `lnk_observation_patient`, `lnk_observation_encounter`) resolve on them:

| FHIR field | OpenMRS source |
|---|---|
| `Patient.id`, `Encounter.id`, `Observation.id` | `person.uuid`, `encounter.uuid`, `obs.uuid` |
| `*.subject.reference` | `Patient/<person.uuid>` |
| `Observation.encounter.reference` | `Encounter/<encounter.uuid>` |
| `meta.lastUpdated` | `coalesce(date_changed, date_created)` |

## Incremental load

Each resource is incremental on `meta.lastUpdated`. The first run reads rows with `date_created >=` `ETHIOEMR_MYSQL_INITIAL_CURSOR`; later runs read rows strictly newer than the stored watermark, so a re-run appends only new rows. `date_created` is the cursor because the generated rows leave `date_changed` NULL. dlt's boundary-row deduplication is disabled (`primary_key=()`) because duplicate safety comes from the strict comparison in SQL.

## Output

```
s3://nhdw-raw/ethioemr/<table>/year=YYYY/month=MM/day=DD/ethioemr_<table>_<ts>_run-<id>_part-<hash>.parquet
s3://nhdw-raw/ethioemr/<table>/year=YYYY/month=MM/day=DD/_manifest.json
```

The processed-zone Job drops the person-identifying columns of these tables (names, MRN, birth date, free text) according to `2_pipelines/staging/scripts/pii_policy.yaml`.

## Running

The Kubernetes Job `ethioemr-ingest` in `1_infrastructure/k8s/base/ingestor-jobs.yaml` runs the image with args `["extract"]`. It reaches the replica at `host.k3d.internal:33306` as the read-only `ingestor` user created by `0_external/sources/EthioEMR/scripts/restore.sh` (password from the `source-creds` Secret).

The image is `nhdw/ethioemr-ingestor`, built by `bundle/scripts/build-images.sh`. Outside the cluster:

```bash
docker run --rm --env-file .env nhdw/ethioemr-ingestor:1.0.0 extract
docker run --rm --env-file .env nhdw/ethioemr-ingestor:1.0.0 -v extract
```

## Configuration

`.env.example` lists every variable.

| Variable | Default | Meaning |
|---|---|---|
| `ETHIOEMR_MYSQL_HOST` | required | MySQL host |
| `ETHIOEMR_MYSQL_PORT` | `3306` | MySQL port (`33306` for the published replica) |
| `ETHIOEMR_MYSQL_DB` | `openmrs` | Database |
| `ETHIOEMR_MYSQL_USER`, `ETHIOEMR_MYSQL_PASSWORD` | user required | Read-only login (`GRANT SELECT`) |
| `ETHIOEMR_MYSQL_RESOURCES` | `Patient,Encounter,Observation` | FHIR resources to emit |
| `ETHIOEMR_MYSQL_INITIAL_CURSOR` | `2020-01-01` | `date_created` floor for the first run |
| `ETHIOEMR_MYSQL_TIMEOUT` | `120` | Connection timeout in seconds |
| `ETHIOEMR_MYSQL_BATCH_SIZE` | `2000` | Rows per fetch from the server-side cursor |
| `MINIO_ENDPOINT` | required | S3 endpoint of the lake |
| `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY` | required | Object-store credentials |
| `MINIO_RAW_BUCKET` | `nhdw-raw` | Target bucket |
| `MINIO_REGION` | `et-addis-1` | S3 region name |
| `DLT_PIPELINE_NAME` | `ethioemr` | Prefix of dlt's pipeline state |
| `OM_LINEAGE_API`, `OM_LINEAGE_JWT` | unset | Enable lineage emission to OpenMetadata |

The `MINIO_*` names are historical; the object store is SeaweedFS.
